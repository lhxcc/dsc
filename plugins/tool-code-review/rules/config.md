# 配置 / 数据文件评审规则

精确优先：只报会导致运行失败、行为错误或安全风险的问题；缩进与排序偏好不报。

## 结构与语法

- 明显的语法错误：重复 key、未闭合的括号/引号、缩进破坏层级（YAML）。
- YAML 隐式类型陷阱：`yes`/`no`/`on`/`off` 被解析为布尔、`1.0` 被当作数字、日期被自动转换。
- 同一配置项在多处定义且取值冲突；环境变量与默认值互相覆盖顺序不明确。

## 安全

- 硬编码密钥、token、证书私钥、真实用户数据提交进仓库。
- 权限过宽：`chmod 777`、`runAsUser: 0`、`privileged: true`、未限制的 CORS `*` 配合凭据。
- CI 配置中不可信输入（PR 标题/分支名）直接插入 shell 命令（脚本注入）。
- 关闭安全校验：`insecureSkipVerify`、`--no-verify`、`strict: false` 且无说明。
- 容器镜像使用 `latest` 标签或未固定 digest（仅在发布/生产配置中报告）。

## 正确性与可维护性

- 引用不存在的文件/脚本/服务名（与同批次改动明显矛盾时）。
- 超时/重试/资源限制缺失或为 0，导致请求可无限挂起。
- 环境相关的绝对路径、仅本机可用的地址被写进共享配置。
- 版本约束过宽（`*`、`>=0`）导致不可复现构建。
