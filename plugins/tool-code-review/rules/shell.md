# Shell / 构建脚本评审规则

精确优先：只报能确证的缺陷；缩进与引号风格由 shellcheck/格式化工具覆盖。

## 引用与分词

- 变量未加引号（`$var`、`$@`、命令替换）导致分词/通配展开错误。
- `for f in $(ls)` 解析文件名；应使用 `for f in *` 或 `find -print0`。
- 期望整体传递时未用 `"$@"`；数组与字符串混用。

## 错误处理

- 缺少 `set -euo pipefail`（或显式错误检查），失败被静默忽略后继续执行危险操作。
- 管道失败只反映最后一个命令（未启用 `pipefail`）。
- `rm -rf "$VAR"` 中 VAR 可能为空/未定义（删除错误目录）。
- `cd` 失败后仍继续在错误目录执行命令。

## 临时文件与清理

- 固定路径临时文件（`/tmp/foo`）导致竞态；应使用 `mktemp`。
- 缺少 `trap` 清理临时目录/后台进程，异常退出后残留。
- 覆盖已有文件前未校验目标。

## 安全

- `eval` 或 `bash -c` 处理外部输入。
- 把不可信输入直接拼进命令/路径（注入、路径穿越）。
- 脚本中硬编码密码/token；`curl -k` 关闭证书校验。
- 从网络下载后直接执行而未校验来源/签名。

## 可移植性与正确性

- GNU 与 BSD/macOS 工具选项差异（`sed -i`、`date -d`、`grep -P`）用在跨平台脚本。
- `[ ]` 与 `[[ ]]` 混用导致字符串比较语义不同；数值比较未用 `-eq` 系列。
- 通配未匹配任何文件时原样传递（`nullglob` 缺失）。
